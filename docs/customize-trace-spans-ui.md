# Customize Future Spans and Traces UI Columns

This guide explains how to shape MLflow traces in this repo so:

- `Inputs` / `Outputs` render correctly in trace summary.
- Traces table columns (`Request`, `Response`, `Session`, `User`, `Tokens`, etc.) are populated.
- `Prompt`/`Version` are populated when using MLflow Prompt Registry.

## 1) Where to customize in this codebase

- LangChain callback path:
  - [`agent_mlflow_telemetry/langchain_callback.py`](../agent_mlflow_telemetry/langchain_callback.py)
- Wrapped client path:
  - [`agent_mlflow_telemetry/llmclient_adapter.py`](../agent_mlflow_telemetry/llmclient_adapter.py)
- Payload builders:
  - [`agent_mlflow_telemetry/chat_payloads.py`](../agent_mlflow_telemetry/chat_payloads.py)
- MLflow write boundary:
  - [`agent_mlflow_telemetry/mlflow_sink.py`](../agent_mlflow_telemetry/mlflow_sink.py)

`MLflowSink` is the final source of truth:

- `_mlflow_inputs` -> `inputs` (span payload)
- `_mlflow_outputs` -> `outputs` (span payload)
- root trace metadata uses `mlflow.trace.session` and `mlflow.trace.user`

## 2) Inputs/Outputs format that works best in UI

For LLM spans, keep outputs in this shape:

```python
{
  "messages": [{"role": "assistant", "content": "telemetry-ready"}],
  "model": "nemotron-3-nano",
  "usage": {"prompt_tokens": 24, "completion_tokens": 59, "total_tokens": 83},
  "response_metadata": {...}
}
```

Why:

- `Response` preview stays plain text (`telemetry-ready`), not quoted JSON.
- summary keeps assistant message plus metadata.
- avoids old `choices` wrapper.

This shape is generated by `build_chat_outputs(...)` in [`chat_payloads.py`](../agent_mlflow_telemetry/chat_payloads.py).

## 3) Traces table column mapping

These are the practical mappings in MLflow 3.10.0 with this adapter:

- `Trace ID`: trace request id (`tr-...`) generated by MLflow.
- `Request`: `trace_info.request_preview` (derived from root span inputs).
- `Response`: `trace_info.response_preview` (derived from root span outputs).
- `Session`: trace metadata `mlflow.trace.session`.
- `User`: trace metadata `mlflow.trace.user`.
- `Trace name`: trace tag `mlflow.traceName` (root span name).
- `Tokens`: trace metrics (`input_tokens`, `output_tokens`, `total_tokens`) from `mlflow.chat.tokenUsage`.
- `Execution time`: `trace_info.execution_time_ms`.
- `Request time`: `trace_info.timestamp_ms`.
- `Run name`: via `mlflow.sourceRun` (active run id) -> run tag `mlflow.runName`.
- `Source`: request metadata like `mlflow.source.name` / `mlflow.source.type`.
- `State`: `trace_info.status` (`OK`/`ERROR`).
- `Prompt`, `Version`: from linked prompt versions (`mlflow.linkedPrompts`).

## 4) How to populate `Prompt` / `Version`

`Prompt` stays empty unless prompt versions are linked to the trace.

### Recommended path

Use Prompt Registry and load prompt during an active MLflow span context:

```python
import mlflow

mlflow.genai.register_prompt(
    name="agent_system_prompt",
    template="You are a helpful assistant.",
    commit_message="init",
)

with mlflow.start_span(name="llm.invoke", span_type="CHAT_MODEL") as span:
    span.set_inputs({"messages": [{"role": "user", "content": "Say hi"}]})
    prompt = mlflow.genai.load_prompt("agent_system_prompt", version=1)
    # use prompt.template when building model call
    span.set_outputs({"messages": [{"role": "assistant", "content": "hi"}]})
```

This writes `mlflow.linkedPrompts` and enables Prompt/Version display.

### Important note for this adapter

This repo currently writes spans with `start_span_no_context` inside `MLflowSink`.
Setting only span attribute `mlflow.linkedPrompts` is not enough to populate trace-level Prompt column.
You need either:

- active-span `load_prompt(...)` flow above, or
- explicit sink extension to write trace tag `mlflow.linkedPrompts`.

## 5) Customize nested spans (tool/mcp/skill)

Nested call spans are emitted here:

- callback path: `_emit_tool_call_spans(...)` in [`langchain_callback.py`](../agent_mlflow_telemetry/langchain_callback.py)
- wrapper path: `_emit_tool_call_spans(...)` in [`llmclient_adapter.py`](../agent_mlflow_telemetry/llmclient_adapter.py)

Current operation naming:

- `tool_call.<type>.<name>` (for example `tool_call.mcp.search_docs`)

To add richer summary fields, add attributes such as:

- `tool_call_id`
- `tool_call_name`
- `tool_call_arguments`
- provider/model markers if useful

## 6) Quick verification checklist

After any change, verify:

1. `Response` preview is plain text (not quoted JSON).
2. summary shows `Assistant` message in Outputs.
3. `response_metadata` is present in span attributes.
4. `Session`/`User`/`Run name` are non-empty for root traces.
5. `Prompt`/`Version` only expected to be non-empty when prompt versions are linked.
